# [MEDIUM] auto-updates does not surface phased APT updates, held packages, or transaction warnings on Ubuntu 26.04

## Environment
- **Project**: `auto-updates`
- **Package**: `auto-updates_1.3.2-1_all.deb`
- **Platform**: `linux / ubuntu 26.04 (x86_64)`
- **Architecture**: `x86_64`
- **Test Node**: `user@10.0.0.166:2205` (`ubuntu-26.04-TEST`)
- **Git Commit**: `7a515ba`
- **Reported Date**: `2026-09-30T18:05:00Z`

## Problem Summary
When `auto-updates-runner` executes on Ubuntu 26.04 LTS with update mode `all`, `apt-get dist-upgrade` defers packages controlled by Ubuntu's phased updates feature (e.g. `gnome-shell`, `gnome-shell-common`, `glycin-loaders`, `glycin-thumbnailers`, `libglycin-2-0`, `libglycin-gtk4-2-0`).

`apt-get` exits with return code 0 even when updates are held back or deferred:
```text
The following upgrades have been deferred due to phasing:
  glycin-loaders glycin-thumbnailers gnome-shell gnome-shell-common libglycin-2-0 libglycin-gtk4-2-0
0 upgraded, 0 newly installed, 0 to remove and 6 not upgraded.
```

Because the exit code is 0 and no package installations occurred (`PKG_STATE_BEFORE == PKG_STATE_AFTER`), `auto-updates-runner` logs:
```text
[2026-09-30 09:55:23] [SUCCESS] Auto-Updates run completed successfully in 2s. (Exit code: 0)
[2026-09-30 09:55:23] [INFO] Package transaction completed: no package changes detected on system.
```
And `auto-updates status` reports a clean status with no pending updates mentioned.

Similarly, when package deprecations, dependency broken states, or conflicts prevent package installation (as occurs on DNF when packages are skipped due to conflicts, or on APT when packages are held or marked broken), `auto-updates` does not distinguish between a truly up-to-date system and a transaction where packages were skipped or deferred.

## Steps to Reproduce
1. On Ubuntu 26.04 LTS (`user@10.0.0.166:2205`), run `sudo auto-updates run`.
2. Notice the runner output completes with exit code 0 and logs "no package changes detected".
3. Run `apt list --upgradable`.
4. Observe that packages are listed as pending / deferred, with no notification or warning emitted by `auto-updates`.

## Proposed Remediation & Patch Design
1. **Phased Updates Detection**:
   - Parse `apt-get dist-upgrade` and `apt-get upgrade` output for phased/held-back notices (`The following upgrades have been deferred due to phasing:` or `The following packages have been kept back:`).
   - Log an informative notice `[INFO] Phased or kept back packages detected: ...` so that the admin has full visibility.
   - Introduce an optional configuration setting in `/etc/auto-updates/auto-updates.conf` (e.g. `INCLUDE_PHASED_UPDATES=true|false`, default `false` to respect distribution safety policy, but allowing automated nodes/servers to pass `-o APT::Get::Always-Include-Phased-Updates=true`).
2. **Transaction Conflict & Failure Detection**:
   - For DNF backends (DNF4 and DNF5): Parse output for `Skipping packages with conflicts:` and `Skipping packages with broken dependencies:`. Emit a `[WARN]` log when packages are skipped so conflicts are not masked as silent success.
   - For APT backends: Parse output for held-back, deferred, or unauthenticated/deprecated packages.
3. **Version Bump & Policy Compliance**:
   - Increment version from `1.3.2` to `1.3.3` across `src/main.sh`, `bin/auto-updates`, `build_rpm.sh`, and `auto-updates.spec`.
   - Add changelog entry in `src/main.sh` and `%changelog` in `auto-updates.spec`.
   - Maintain strict `rpmlint` 0-error / 0-warning compliance.
